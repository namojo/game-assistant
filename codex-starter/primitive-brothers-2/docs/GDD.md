## 0. 한 장 요약

### 0.1 컨셉 문장

> **8년째 형님들을 키워온 방치형 유저가, 빙하기에 쫓기는 원시 부족의 캠프를 경영하며 형님들을 강화해 사냥터를 밀어 올리고, 세대가 끝날 때마다 남는 「불씨」와 부족 유산이 다음 세대를 반드시 더 멀리 보내기 때문에 계속한다.**

- **누가(플레이어 판타지)**: 부족장. 전작의 "형님을 키우는 사람"에서 "형님들을 거느린 부족을 경영하는 사람"으로 한 칸 올라간다.
- **무엇을(핵심 동사)**: 강화한다 → 밀어 올린다 → 캠프를 짓는다 → 세대를 넘긴다.
- **왜 계속하는가(락인 장치)**: ① 불씨 노드는 절대 리셋되지 않는 단조 증가 자산이고 ② 형님 도감·스킨·탈것·유산은 세대를 넘어 누적되며 ③ 다음 세대는 수식상 반드시 직전 세대보다 멀리 간다(`p_ratio = 1.15`, 6.2절).

### 0.2 기본 정보

| 항목 | 내용 |
|---|---|
| 장르 | 방치형(키우기) RPG + 경량 부족 경영 메타 |
| 타겟 | 1차: 전작 장기 유저(콘텍스트 락인 보유층). 2차: 방치형 경험자 중 "숫자만 오르는 게임"에 물린 층 |
| 플랫폼 | 프로토타입 = 웹(TypeScript/Canvas). 본편 = Android 우선, Google Play Games on PC, 이후 iOS·Steam 검토 |
| 세션 설계 | 1일 2세션 × 30~60분 + 오프라인 누적(무과금 8시간 상한) |
| MVP 범위 | 코어 루프 + 강화 + 장비 + 스테이지·보스 + 프레스티지 + 오프라인 + 결정적 코어 + 헤드리스 시뮬레이터 (13장) |
| 수익모델 | 비확률(스킨·시즌 패스·광고 제거·성장 패키지) 중심, 확률형은 「형님 원정 소집」 1종만 + 천장 내장 (7장) |

### 0.3 전작 대비 차별점 3개

1. **부족 캠프 메타**: 스테이지 진행만이 아니라 캠프 건물(화톳불·사냥막·뼈공방)이 골드·불씨·장비 수급률을 결정한다. 대형사 키우기 신작(던파 키우기 등)이 IP 전투력 경쟁으로 붙는 구간을 비켜 **경영·배치**라는 다른 동사로 차별화한다(시장분석가 입력: 같은 카테고리 정면 경쟁 회피).
2. **빙하기 세대 교체 프레스티지**: 리셋이 패널티가 아니라 서사(빙하기가 와서 부족이 이동하고 형님의 아들 세대가 이어받는다)다. 전작에 프레스티지가 있었는지 미확인이므로 `(가정)` 신규로 취급한다.
3. **확률형 최소화 + 검증 내장**: 전작의 슬롯머신을 폐기하고, 남기는 확률형 1종에는 표기 위치·N회 검증·천장을 설계 단계에서 못 박는다(4.3 규제 트렌드 대응). 매출은 스킨·시즌 패스·광고 제거로 옮긴다.

## 1. 컨셉과 플레이어 판타지

### 1.1 세계관 한 문단

마지막 간빙기가 끝나간다. 형님들은 여전히 뼈몽둥이를 들고 나가서 매머드를 두들기지만, 북쪽에서 얼음이 내려온다. 부족은 캠프를 세우고, 사냥하고, 얼음이 닿으면 짐을 싸서 남쪽으로 내려간다. 내려갈 때 가져갈 수 있는 것은 **꺼지지 않은 불씨**와 **형님들이 남긴 이야기(도감)** 뿐이다. 다음 세대의 형님들은 그 불씨로 더 빨리 강해지고, 그래서 더 멀리 간다.

### 1.2 톤 앤 매너

전작의 자산 중 가장 방어력이 높은 것은 밸런스가 아니라 **유머와 캐릭터 호감도**다(리뷰 신호: 장기 유저 충성도, 우호적 과금 평가). 따라서 톤은 전작을 그대로 계승한다.

- 형님들은 진지하게 멍청하다. 대사는 짧고, 상황에 비해 과하게 비장하다.
- 실패·리셋 연출조차 개그로 처리한다(빙하기 컷신에서 형님이 불씨 대신 고기를 챙긴다).
- **금지**: 다크 판타지, 미소녀 뽑기 연출, 숫자 이펙트만 남는 화면. 전작 유저가 "다른 게임이 됐다"고 느끼는 순간 콘텍스트 락인이 무효가 된다.

### 1.3 핵심 감정 곡선

| 구간 | 플레이어가 느껴야 하는 것 | 설계 장치 |
|---|---|---|
| 0~10분 | "손이 안 가는데 숫자가 오른다" | 자동 전투 + 원탭 강화, 첫 형님 즉시 지급 |
| 10~60분 | "형님이 늘어난다" | 형님 2·3번 해금(s=12, s=35) |
| 약 55분 | "안 밀린다" | 첫 벽(밸런스 모델 목표표 기준 53.5분, s≈110) |
| 1~2시간 | "리셋했더니 더 빨라졌다" | 첫 세대 교체(s=120 도달 시 해금) |
| D3~D7 | "캠프가 내 것이 된다" | 캠프 건물 3종·스킨 1종 무료 지급 |
| D30 | "8년 굴릴 물건이다" | 도감 완성률·시즌·랭킹 |

## 2. 전작 시스템 분류

전작에서 **확인된** 시스템(진단자 전달): 문명(단계 진행), 강화, 장비 합성, 토템, 슬롯머신, 보스토벌, 형님의 탑, 길드, 월드 시스템(3.60), 스킨(3.60), 월드 몬스터 도감·카드(3.60), 탈것(3.60). 아래 표의 "전작 규칙" 열은 **명칭만 확인된 것**이며 내부 규칙은 전부 `(가정)`이다.

| 전작 시스템 | 분류 | 신작에서의 처리 | 이유 |
|---|---|---|---|
| 문명 (단계 진행) | **개선** | 「부족 시대」로 재설계. 100스테이지마다 시대 승급, 시대별 전역 배수 + 캠프 건물 해금 | 단계 진행은 방치형의 중장기 목표축으로 검증된 구조. 다만 전작에서 스테이지와 별도 축이었는지 미확인 `(가정)` → 신작은 **스테이지에 종속**시켜 시뮬레이터에서 단일 변수로 다룬다 |
| 강화 | **계승** | 형님별 레벨 강화. 비용 등비, 25레벨마다 배수 점프 | 코어 루프의 골드 싱크. 변경 이유가 없다 |
| 장비 합성 | **개선** | 확률 합성 → **결정적 합성(같은 등급 4개 = 상위 1개, 100%)** + 별도의 선택적 확률 강화 1종에만 확률 배치 | 확률형 규제(4.3)에서 가장 먼저 문제가 되는 구간. 결정적으로 만들면 표기·검증 의무 자체가 사라지고 시뮬레이터 재현성도 올라간다 |
| 토템 | **개선** | 독립 시스템 폐지 → 프레스티지 통화 「불씨」 노드 트리에 흡수. 외형은 토템 기둥 유지 | 영구 % 보너스 축이 둘(토템·프레스티지)이면 곱셈 상호작용이 벽을 예측 불가하게 만든다(8.2 QA 진단과 동일한 문제) |
| 슬롯머신 | **폐기** | 삭제. 대체재 = 보상형 광고 슬롯(7.4)과 일일 무료 「사냥 제비」(확정 보상 5종 순환, 확률 없음) | 확률형 아이템 규제 리스크 대비 매출 기여가 불투명. 비확률 수익 전환 트렌드(4.3)와 정반대 방향 |
| 보스토벌 | **개선** | 「보스 원정」. **설정을 서버에 영속화**하고 클라이언트 로컬 캐시는 보조로만 사용 | 리뷰에서 확인된 UX 마찰(기본 설정 초기화)의 직접 대응. 회귀 테스트 필수 시나리오로 등록(11.3) |
| 형님의 탑 | **계승** | 「얼음 절벽」. 층별 고정 조건, 주 1회 보상 리셋 | 주간 콘텐츠 축. 전투 시뮬레이터를 그대로 재사용 가능 |
| 길드 | **확장(MVP 제외)** | v1.2 이후. MVP에는 스키마 자리만 만든다 | 9명 팀에서 소셜 기능은 CS·밸런스 부하가 크다. 신작 검증 단계에서 뺀다 |
| 월드 시스템 (3.60) | **개선** | 「빙하기 원정」. 월드 = 스테이지 1000 단위 구간 + 전용 몬스터 팔레트 | 3.60에서 추가된 최신 축이므로 유저 수용성이 검증된 편. 다만 스테이지와 이중 진행축이 되면 밸런스가 꼬이므로 스테이지 구간으로 정규화 |
| 스킨 (3.60) | **계승·강화** | 비확률 수익의 1순위 상품. 형님별 3종 이상, 시즌 패스 보상으로도 지급 | 3.60 스킨 도입은 비확률 수익 전환 신호로 읽힌다(4.3). 아트 AX 생산량이 그대로 매출이 되는 유일한 축 |
| 월드 몬스터 도감·카드 (3.60) | **계승** | 「형님의 이야기」 도감. 카드 = 도감 완성 시 영구 % 보너스 | 프레스티지 유지 자산으로 딱 맞는다. 콘텐츠 1종 = 테이블 1행 + 에셋 1종 구조에 가장 잘 맞는 시스템 |
| 탈것 (3.60) | **개선** | 부족 자산으로 승격. 탈것 = 오프라인 상한/이동(스테이지 스킵) 보너스 담당, 전투력 기여는 소폭 | 전작에서 전투력 배수였는지 미확인 `(가정)`. 신작에서는 **전투력 축에서 분리**해 곱셈 인플레를 줄인다 |
| — | **신규** | 부족 캠프(건물 배치·생산) | 차별화 축 ①. 대형사 키우기와 다른 동사 |
| — | **신규** | 세대 교체 프레스티지 + 불씨 노드 | 차별화 축 ②. 리셋 = 서사 |
| — | **신규** | 시즌 패스 + 광고 제거 | 차별화 축 ③. 비확률 매출 주축 |

## 3. 코어 루프

### 3.1 다이어그램

```
        ┌───────────────────────────────────────────────┐
        │                                               │
        v                                               │
  [자동 전투] --(몬스터 처치)--> [골드] --(강화)--> [DPS 상승]
        │                           │                   │
        │                           └--(장비 합성)-----> │
        │                                               │
        └--(웨이브 클리어)--> [스테이지 +1] -------------┘
                                  │
                                  v
                           [보스 스테이지 s%10==0]
                                  │
                      30초 내 처치 실패 = ★벽★
                                  │
              ┌───────────────────┴────────────────────┐
              v                                        v
   [사냥터 자동 최적화 → f*에서 파밍]        [오프라인 보상 / 광고 x2]
              │                                        │
              └──────────────> [강화 재개] <───────────┘
                                  │
                       벽이 30분 이상 지속되면
                                  v
                        [세대 교체(프레스티지)]
```

### 3.2 초 단위 흐름 (결정적 코어 기준)

고정 타임스텝 `dt = 100ms`. 코어는 렌더링 없이 동일 시드 → 동일 결과를 보장한다.

| 틱 | 처리 |
|---|---|
| 1 | 전투 해상도 계산: `DPS_total` 산출 (5.1~5.4의 모든 배수를 곱한 값) |
| 2 | 현재 웨이브 잔여 HP에서 `DPS_total × dt` 차감. 몬스터 1마리 처치 최소 시간 `t_min = 0.5초` 강제(연출·스폰 시간) |
| 3 | 처치 시 골드 지급 `G(s) × 골드배수`, 도감 카운트 +1, 드랍 롤 |
| 4 | 웨이브(일반 4마리 / 보스 1마리) 소진 시 스테이지 +1. 보스 스테이지는 30초 타이머 |
| 5 | 자동 강화 ON이면 `ΔDPS/비용` 최대 항목을 구매 가능한 만큼 반복 구매 |
| 6 | 보스 타임아웃 시 `wall_hit` 이벤트 발행 후 사냥터 자동 최적화 진입 |

### 3.3 벽 정의 (밸런스 모델과 동일 수치)

| 벽 종류 | 판정식 | 임계값 |
|---|---|---|
| 일반 웨이브 벽 | `n_mob × HP(s) / DPS_total > t_wall` | `n_mob=4`, `t_wall=30초` |
| 보스 벽 (주 벽) | `m_boss × HP(s) / DPS_total > t_wall` | `m_boss=7`, `t_wall=30초` |
| 체감 벽 | 30분 이동창 기준 최고 스테이지 증가 < 5 | `window_sec=1800`, `window_gain=5` |

**첫 벽 목표 시각: 플레이 53.5분, 스테이지 약 110** (밸런스 모델 **8.2절 검산값**. 7절 목표표의 설계 의도는 "약 55분, s≈110"이며 검산 편차 −2.7%). 설계상 보스 벽이 일반 벽보다 항상 먼저 온다(보스 전선이 일반 전선보다 약 10스테이지 낮다 — 밸런스 모델 4.3).

### 3.4 벽을 넘게 하는 자원

| 벽 상황 | 넘는 수단 | 비용 |
|---|---|---|
| 보스 30초 초과, 격차 작음 | 사냥터 자동 최적화 + 5~15분 파밍 | 시간 |
| 격차 중간 | 오프라인 보상 수령 (8시간 상한) | 시간(접속 주기) |
| 격차 중간 | 광고 시청 오프라인 ×2 | 광고 1회 |
| 격차 큼 | 장비 티어 업(결정적 합성) | 장비 파편 |
| 격차 매우 큼 | **세대 교체(프레스티지)** | 런 리셋 |
| 즉시 | 성장 패키지(골드 +20% / DPS +12%) | 결제 |

## 4. 메타 루프

### 4.1 세대 교체 (프레스티지) — 「빙하기」

**테마**: 얼음이 캠프까지 내려오면 부족은 남쪽으로 이동한다. 형님들은 늙고, 그 아들들이 몽둥이를 물려받는다. 가져가는 것은 불씨(`ember`)와 부족의 기억(도감·스킨·탈것·유산)이다.

**발동 조건**
- 최초 해금: 최고 스테이지 `s ≥ 120` 도달
- 이후 권장선: `run_best ≥ 1.15 × last_best` (게임이 "지금 넘기면 이득" 배너를 띄운다)
- 강제하지 않음. 벽에서 30분 정체 시에도 권장 배너 노출

**통화 산출**: `Q = floor(0.35 × s_reached^1.45)` (밸런스 모델 6.1)

| 도달 s | 120 | 200 | 360 | 450 | 700 | 950 | 1150 |
|---|---|---|---|---|---|---|---|
| 획득 불씨 Q | 362 | 759 | 1,781 | 2,461 | 4,671 | 7,273 | 9,595 |

**리셋 / 유지 표** (필수)

| 대상 | 리셋 | 유지 | 비고 |
|---|---|---|---|
| 형님 강화 레벨 | ● | | 모든 형님 L=0 |
| 형님 해금 상태 | ● | | 스테이지 재도달로 재해금 (`unlock_stage`) |
| 보유 골드 | ● | | |
| 현재/최고 스테이지(런) | ● | | 시작 스테이지는 `floor(0.5 × best_ever)`로 보정 |
| 장비 인벤토리·장착 | ● | | 스테이지 드랍으로 빠르게 회복(등급 = 스테이지 종속) |
| 캠프 건물 레벨 | ● | | 단, 건물 **해금 상태**는 유지 |
| 불씨(`ember`) 잔액·노드 | | ● | 단조 증가. 절대 리셋 없음 |
| 부족 유산(불씨 노드 효과) | | ● | 공격 %, 골드 %, 시작 스테이지, 오프라인 상한 |
| 몬스터 도감·카드 | | ● | 카드 % 보너스 유지 |
| 스킨 보유·장착 | | ● | 결제 자산은 절대 리셋 금지 |
| 탈것 | | ● | |
| 시즌 패스 진행도·레벨 | | ● | |
| 도전과제·통계 | | ● | |
| 우편함·미수령 상품 | | ● | **결제 미수령 방지(리뷰 이슈 대응)** |

**불씨 노드 트리**: 노드 `A`번째의 비용 `cost(A) = 5 + 0.7A` 불씨, 효과 `공격력 ×1.05` 누적(`M = 1.05^A`). 비용이 등비가 아니라 **등차**인 것이 핵심이다(밸런스 모델 6.2에 근거: 등비 비용이면 30일차 필요 배수를 만들 수 없다).

| 노드 수 A | 10 | 50 | 100 | 200 | 400 | 589 |
|---|---|---|---|---|---|---|
| 누적 불씨 | 82 | 1,108 | 3,965 | 14,930 | 57,860 | 124,161 |
| 영구 공격 배수 M | 1.63 | 11.5 | 132 | 1.73e4 | 2.99e8 | 3.02e12 |

노드는 4개 계열로 분기한다: **불(공격 %) / 사냥(골드 %) / 발자국(시작 스테이지) / 가죽(오프라인 상한)**. MVP는 불 계열만 구현하고 나머지는 스키마만 둔다(13장).

## 5. 시스템 상세

각 시스템은 `목적 / 규칙 / 입력·출력 자원 / 테이블 / 범위` 형식이다. 테이블 스키마는 8장.

### 5.1 형님 (동료)

- **목적**: DPS의 주축이자 캐릭터 애착의 담지자. 아트 거버넌스상 **원화는 사람이 그린다**(전략가 입력).
- **규칙**: 6종. `unlock_stage = [1, 12, 35, 75, 150, 280]`에 도달하면 자동 해금. 개별 레벨 `L_i`를 골드로 강화.
  - `ATK_i(L) = atk0_i × (1 + 0.12 L) × 1.75^floor(L/25)`
  - `atk0_i = 6 × 4^i`, 강화 비용 `C_i(L) = 25 × 4^i × 1.075^L`
  - 형님별 패시브 1종(예: 3번 형님 "고기 냄새" — 골드 +8%). MVP는 패시브 없음.
- **입력**: 골드 · **출력**: DPS
- **테이블**: `brothers`, `upgrades`
- **범위**: MVP 4종(i=0..3), 확장 6종

### 5.2 강화

- **목적**: 골드의 1차 싱크이자 벽의 주 원인.
- **규칙**: 형님별 레벨 1씩 구매. `x1 / x10 / x100 / MAX` 버튼. **자동 강화** 토글(ΔDPS/비용 최대 항목 자동 구매) — 방치형의 필수 편의.
  - 25레벨 배수 점프(`×1.75`)는 연출 이벤트로 승격한다(형님이 새 몽둥이를 든다).
- **입력**: 골드 · **출력**: ATK
- **테이블**: `upgrades`
- **범위**: MVP

### 5.3 장비 · 합성

- **목적**: 골드 외 2차 성장축. 벽 돌파의 계단식 점프 제공.
- **규칙**:
  - 장비는 스테이지 드랍. 등급 `k`(0~12), 드랍 등급은 `floor(s/60)` 중심의 결정적 분포.
  - 등급 배수 `E(k) = 1.20^k`, 최대 `k=40`까지 확장 가능.
  - **합성은 결정적**: 동일 등급 4개 → 상위 등급 1개, 성공률 100%. 확률 없음 → 표기 의무 없음.
  - **선택적 확률 요소**: 「뼈 갈기」 — 장비 1개를 소모해 **추가 옵션 1줄**을 부여(7.3의 확률형 1종). 미획득 시에도 재료는 「갈린 뼈」로 환급 → 순수 손실 없음. 천장 20회.
  - 장비는 세대 교체 시 리셋(4.1). 스테이지 종속이라 재획득이 빠르다.
- **입력**: 장비 파편·골드 · **출력**: 공격 배수
- **테이블**: `equipment`
- **범위**: MVP(드랍 + 결정적 합성), 확장(뼈 갈기)

### 5.4 토템 · 유산 (불씨 노드)

- **목적**: 프레스티지 통화의 유일한 사용처. 세대 간 단조 증가 보장.
- **규칙**: 4.1의 노드 트리. 노드는 되팔 수 없다(리스펙 없음 — 시뮬레이터 상태공간을 줄이기 위한 의도적 제약).
- **입력**: 불씨 · **출력**: 영구 공격/골드 %, 시작 스테이지, 오프라인 상한
- **테이블**: `totems`
- **범위**: MVP(불 계열), 확장(4계열)

### 5.5 스테이지 · 보스

- **목적**: 진행의 척도이자 모든 곡선의 독립변수.
- **규칙**:
  - `HP(s) = 25 × 1.058^(s-1) × (1 + 0.25 × floor(s/10))`
  - 일반 스테이지 몬스터 4마리, 매 10번째는 보스 1마리(`HP × 7`, 제한 30초)
  - 골드 `G(s) = 8 × 1.052^(s-1)`, 보스는 `×10`
  - 100스테이지마다 **시대 승급**(연출 + 캠프 건물 해금), 1000스테이지마다 **월드 전환**(몬스터 팔레트 교체)
  - **사냥터 자동 최적화**: 벽에 막히면 `HP(f) ≤ DPS × 0.5`를 만족하는 최대 `f`로 자동 귀환. 골드/초가 최대가 되는 지점이다(밸런스 모델 4.3).
- **입력**: 시간·DPS · **출력**: 골드·장비·도감
- **테이블**: `stages`, `monsters`
- **범위**: MVP

### 5.6 탑 / 원정

- **목적**: 방치로 풀리지 않는 도전 축(세션 유입 동기).
- **규칙**: 얼음 절벽 — 층별 고정 HP·고정 제한시간, 오프라인 진행 없음. 보스 원정 — 일 3회, 딜량 누적 랭킹.
- **입력**: 도전 횟수 · **출력**: 불씨·장비 파편
- **테이블**: `stages`(type 필드로 구분), `events`
- **범위**: 확장

### 5.7 길드 (확장)

- v1.2. MVP에는 `guild_id` 필드 자리만 둔다. 9명 팀 기준 CS 부하가 가장 큰 기능이므로 신작 검증 종료 후 판단.

### 5.8 탈것 · 스킨

- **탈것**: 부족 자산. 효과는 **오프라인 상한 +시간**, **시작 스테이지 +N**, **이동 연출**. 전투력 기여는 최대 +5%로 제한(곱셈 인플레 억제).
- **스킨**: 형님별 외형 교체. 밸런스 영향은 **최대 +5% 단일 옵션**으로 상한을 둔다(Pay-to-Win 회피, 비확률 상품의 신뢰 유지). 스킨은 **원화 1장 → AI 변형 N종** 구조로 설계한다(9장).
- **테이블**: `mounts`, `skins`
- **범위**: 스킨 MVP(1종 무료 지급으로 시스템 검증), 탈것 확장

### 5.9 도감 · 카드

- **목적**: 프레스티지 유지 자산 + 콘텐츠 소비 속도 조절.
- **규칙**: 몬스터 종별 누적 처치 10/100/1,000에서 카드 3단계 획득. 카드는 전역 % 보너스(공격 +0.5% / 골드 +1% / 드랍 +1% 중 1종).
- **테이블**: `collection`, `monsters`
- **범위**: MVP(카운트·보너스만), 확장(카드 아트·도감 UI)

### 5.10 캠프 (신규)

- **목적**: 차별화 축. "숫자 올리기" 외의 손맛.
- **규칙**: 5×5 격자에 건물 배치. 건물 3종으로 시작.
  - 화톳불(bonfire): 인접 건물 효율 +10%, 불씨 획득 +5%
  - 사냥막(hunt_hut): 골드 획득 +X%
  - 뼈공방(bone_shop): 장비 드랍률 +X%
  - 건물 레벨은 골드로 강화, **세대 교체 시 레벨 리셋 / 해금 유지**
- **인접 보너스**는 배치 퍼즐성을 만들되, 최대 효과와 최소 효과 차이를 **1.3배 이내**로 제한한다(배치를 틀려도 게임이 막히지 않도록).
- **테이블**: `camp_buildings`(확장 스키마, 8.13)
- **범위**: 확장(v1.1). MVP는 화톳불 1종 고정 보너스만.

### 6.3 인플레이션 규칙

이벤트·보상의 크기는 **절대 수치로 정의하지 않는다.** 반드시 해당 시점 1시간 골드 수입의 배수로 정의한다.

| 보상 종류 | 크기 |
|---|---|
| 일일 출석 | 1시간 수입 |
| 광고 1회(즉시 골드) | 0.5시간 수입 |
| 오프라인 8시간(무과금) | 4.8시간 수입 (`8 × 0.6`) |
| 오프라인 8시간 + 광고 | 9.6시간 수입 |
| 오프라인 12시간(패스) | 7.2시간 수입 |
| 기간 이벤트 보스 클리어 | 3~10시간 수입 |
| 시즌 패스 골드 보상(1레벨당) | 0.3시간 수입 |

`1시간 수입 = 3600 × G(f*) / max(HP(f*)/DPS, 0.5)` — 서버/코어가 런타임에 계산해 지급한다. 테이블에는 **배수만** 넣는다(`events.reward_hours`).

### 7.3 확률형 요소 — 「뼈 갈기」 (유일)

| 항목 | 규칙 |
|---|---|
| 대상 | 장비 1개에 추가 옵션 1줄 부여 |
| 표기 확률 | 전설 0.5%(**5,000 ppm**) / 영웅 3%(**30,000 ppm**) / 희귀 15%(**150,000 ppm**) / 일반 81.5%(**815,000 ppm**). 테이블 저장값은 정수 ppm이고 **합 = 1,000,000**이다(8.0) |
| 실패 개념 | 없음. 모든 시행이 옵션 1줄을 부여한다(등급만 다름) |
| 천장(pity) | **20회 누적 시 다음 시행 영웅 이상 확정**. 40회 누적 시 전설 확정. 천장 카운터는 계정 영구 보존, 세대 교체로 리셋되지 않음 |
| 천장 표시 | 시행 UI에 "영웅 확정까지 N회" 상시 표시 |

**확률 표기 위치 (4곳 전부 필수)**
1. 「뼈 갈기」 실행 버튼 바로 위 — 전체 확률표 인라인 노출(접기 금지)
2. 게임 내 `설정 > 확률 정보` 상시 화면
3. 스토어 상품 상세 페이지 (해당 시행에 원석이 관여할 경우)
4. 공식 홈페이지 확률 공개 페이지 (버전별 이력 보존)

**검증 방식 (시뮬레이터 회귀 테스트로 고정)**
- 테이블 표기값 `ppm`에 대해 `p = ppm / 1_000_000`으로 변환한 뒤, `N` 시행 관측 빈도가 `p ± 3√(p(1-p)/N)` 안에 있어야 한다. **판정 입력은 언제나 정수 ppm이고, 소수 `p`는 계산 중간값이다.**

| 표기값(ppm) | 표기 p (= ppm/1e6) | ±3σ | 허용 구간 | 상대오차 | 권장 N |
|---|---|---|---|---|---|
| **5,000** (0.5%) | 0.005 | 0.000669 | [0.004331, 0.005669] | 13.4% | **N = 1,800,000** |
| **30,000** (3%) | 0.03 | 0.001618 | [0.028382, 0.031618] | 5.4% | N = 100,000 |
| **150,000** (15%) | 0.15 | 0.003387 | [0.146613, 0.153387] | 2.3% | N = 100,000 |
| **815,000** (81.5%) | 0.815 | 0.003676 | [0.811324, 0.818676] | 0.5% | N = 100,000 |

> **주의(코딩 에이전트 필독)**: `5,000 ppm`(p = 0.005)에서 N=100,000은 3σ 상대오차 13.4%로 ±10% 기준을 만족하지 못한다. 희소 확률은 `N ≥ 900·(1−p)/p` (3σ 상대오차 ±10% 기준)로 시행수를 올려야 한다. **0.5%의 산식값은 N ≈ 1.8e5(179,100)이며, 본 설계는 여유를 두어 N = 1,800,000을 채택한다**(빌드 플랜 6.5). 채택 N의 3σ는 0.005 ± 0.000158이다.
- 테스트는 **표기 테이블(`balance.drop_rates_ppm`)의 정수 ppm 값을 직접 읽어** 구현 RNG 결과와 비교한다. 상수를 테스트에 하드코딩하면 검증 의미가 사라진다. 4개 값의 **정수 합이 1,000,000**임을 같은 테스트에서 단언한다.
- 천장 테스트: 40회 연속 시행 1,000회 반복 시 전설 미획득 케이스가 **0건**이어야 한다(결정적 단언).

## 8. 데이터 스키마

### 8.0 공통 규칙

- 형식: JSON 배열(1테이블 1파일). 경로 `data/{table}.json`. 스키마 파일 `schema/{table}.schema.json`(JSON Schema draft 2020-12).
- 모든 테이블의 1번 필드는 `id`(string, snake_case, 전역 유일).
- 수치 단위: 골드·HP·ATK는 `number`(f64). 배수는 `number`. 시간은 초(`number`).
- **확률·비율은 부동소수 0~1이 아니라 정수 ppm(백만분율)으로 관리한다.** 필드명에 `_ppm` 접미를 붙이고, 값은 **0 이상 1,000,000 이하의 정수**다. 예: 0.5% = `5000`, 3% = `30000`, 35% = `350000`.
- **변환 규칙**: 로더는 테이블을 읽는 즉시 `p = ppm / 1_000_000`으로 변환해 코어에 넘긴다. 코어·테스트·UI는 **테이블에서 읽은 ppm 값만** 쓰고 부동소수 확률을 파일에 다시 쓰지 않는다. 수식 설명문에서 `p`를 소수로 표기하는 것은 허용하되 ppm을 병기한다.
- **스키마 제약**: 확률 필드는 `"type": "integer"`, `"minimum": 0`, `"maximum": 1000000`. 같은 시행의 확률 집합은 **정수 합이 정확히 1,000,000**이어야 한다(부동소수 허용 오차가 필요 없어진다).
- 근거: 부동소수 오차는 "표기와 구현이 같다"는 증명을 흐리는 가장 흔한 원인이고, 이 프로젝트에서 그 증명은 법적 방어 수단이다(전략 청사진 4.3.1, 기획서 부록 E의 고객 약속, 빌드 플랜 3.1).
- 버전: 모든 파일 상단 형제 파일 `data/_manifest.json`에 `{table, version, checksum}` 기록. 밸런스 변경 시 버전 +1 → 시뮬레이터가 곡선 diff 리포트를 자동 생성.
- **에셋은 테이블에 파일 경로를 쓰지 않는다. `asset_id`만 쓴다.** 경로 해석은 `assets/_index.json`이 담당한다.

### 8.1 에셋 id 규칙 (원본/변형 분리)

```
{kind}_{family}_{index}[_{variant}]

kind    : bro | mon | eqp | skn | mnt | tot | bg | ui | fx | card
family   : snake_case 계열명 (예: thak, mammoth, bone_club)
index    : 3자리 0패딩 (001~999)
variant  : 변형 접미사. 없으면 원본(source)
```

**변형 접미사 규칙**

| 접미사 | 의미 | 생성 주체 |
|---|---|---|
| (없음) | 원본 원화 | **사람** |
| `_pXX` | 팔레트 변형 (등급/월드) | AI |
| `_sXX` | 스케일 변형 | AI |
| `_oXX` | 의상 변형 (스킨) | AI(원화가 감수) |
| `_icon` | 아이콘 크롭 | AI/자동 |
| `_silh` | 실루엣(미발견 도감) | 자동 |

예: `bro_thak_001`(원본, 사람) → `bro_thak_001_o02`(스킨 변형, AI) / `mon_mammoth_003`(원본) → `mon_mammoth_003_p05`(5등급 팔레트, AI)

**디렉터리 분리 (거버넌스 강제)**

```
assets/
  source/        # 사람 원화. AI 생성물 반입 금지. 학습 데이터 원본.
    bro_thak_001.png
  gen/           # AI 생성 변형. 반드시 source_id를 manifest에 기록.
    bro_thak_001_o02.png
  _index.json    # {asset_id, path, origin: "human"|"ai", source_id, style_model, reviewed_by, reviewed_at}
```

`origin: "ai"`인 항목은 `source_id`와 `reviewed_by`가 **필수**다. 비어 있으면 빌드 실패시킨다. 이것이 "핵심 캐릭터 원화는 사람" 거버넌스를 코드로 강제하는 방법이다.

## 9. 아트 방향과 에셋 파이프라인

### 9.1 아트 방향

전작 스타일을 **그대로** 승계한다(자사 원화 LoRA가 이미 그 스타일로 학습되어 있다는 전략가 입력 전제). 2D, 두꺼운 외곽선, 과장된 실루엣, 채도 높은 원색.

### 9.2 원본 / 변형 분리 (거버넌스)

| 에셋 종류 | 생산 주체 | 근거 |
|---|---|---|
| 형님 원화(6종 × 기본 포즈) | **사람** | 핵심 캐릭터. 8년 IP의 정체성 |
| 형님 스킨 의상 변형 | AI 생성 → **원화가 감수** | 원화 1장 → N종 |
| 몬스터 원본(계열당 1종) | 사람 | 계열 실루엣이 세계관을 만든다 |
| 몬스터 팔레트/스케일 변형 | AI | 등급·월드별 `_pXX`, `_sXX` |
| 장비 아이콘 원본 | 사람 | |
| 장비 등급 팔레트 | AI | `_p{tier}` 자동 생성 |
| 배경·타일 | AI | |
| UI 아이콘 | AI | |
| 카드 일러스트 | AI (원본 재구성) | |
| 스프라이트 애니메이션 프레임 | **사람** | 프레임 간 일관성은 현 시점 AI 한계(보고서 8.1 명시) |

### 9.3 등급 팔레트 규칙 (변형 자동화의 근거)

```
tier k -> 팔레트 회전각 hue_shift(k), 채도 sat(k), 림라이트 색 rim(k)
k:  0 회색  1 흰색  2 녹색  3 청색  4 보라  5 주황  6 적색  7 금색 ...
```

- 등급 팔레트는 **테이블(`palettes.json`)에 정의**하고 배치 스크립트가 원본 1장에서 전 등급을 생성한다. 아티스트가 등급별로 그리는 일은 없어야 한다.
- 생성물은 Vision LLM 스타일 검수(팔레트·선 굵기·실루엣·해상도)를 통과해야 `assets/gen/`에 커밋된다.

### 9.4 콘텐츠 1종 추가 비용 (설계 검증 기준)

| 콘텐츠 | 추가 비용 | 합격? |
|---|---|---|
| 몬스터 1종 | `monsters` 1행 + 원본 1장(사람) + 팔레트 N장(자동) | ○ |

## 10. 라이브 운영 훅

### 10.1 이벤트 타입

| 타입 | 주기 | 내용 | 테이블만으로 가능? |
|---|---|---|---|
| `raid_boss` | 주 1회 | 기간 한정 보스, 누적 딜량 보상 | ○ (`events` + `monsters` 1행) |
| `collect` | 격주 | 기간 재화 수집 → 교환소 | ○ |
| `boost` | 주말 | 골드 ×2 / 드랍 ×2 / 불씨 ×1.5 | ○ |
| `season` | 28일 | 패스 + 스킨 + 팔레트 교체 | ○ (`events`+`skins`+`monsters`) |

**운영 원칙**: 이벤트 보상은 절대 수치가 아니라 `reward_hours`(6.3)로 정의한다. 이 규칙 하나가 8년 운영에서 경제 붕괴를 막는다.

### 10.2 시즌 구조

- 28일 고정. D-3에 다음 시즌 예고, D+0 자동 전환.
- 시즌 전환 체크리스트(운영 에이전트 자동화 대상): 테이블 3종 교체 → 시뮬레이터 회귀(목표 벽 표 재검산) → 확률 검증 테스트 → 스토어 상품 노출 조건 갱신 → 공지.

### 10.3 랭킹

| 랭킹 | 집계 | 리셋 | 보상 |
|---|---|---|---|
| 최고 스테이지 | 계정 `best_ever` | 없음(명예) | 칭호 |
| 주간 사냥 | 주간 누적 처치 | 주 | 불씨 |
| 시즌 절벽 | 최고 층 | 시즌 | 스킨 |

- 랭킹은 100인 단위 그룹 랭킹으로 운영한다(전체 랭킹은 상위 0.1%만 동기부여가 된다).

2. 앱 강제 종료 중 결제 완료 → 재기동 시 미수령 상품 복구(우편함)
3. 보스 원정 설정 변경 → 앱 재시작 → **설정 유지** (전작 UX 마찰 직접 대응)
4. 세대 교체 → 유지 자산 12종 전부 보존 (4.1 표 기준 단언)
5. 확률 검증(7.3) N회 시행 + 천장 단언

### 12.2 연출 원칙

- **숫자가 주인공이다.** 데미지 숫자, 골드 획득량, 레벨업 팝이 화면의 리듬을 만든다. 이펙트가 숫자를 가리면 안 된다.
- 25레벨 배수 점프, 시대 승급, 세대 교체는 **정지 연출 3종**(짧은 컷인). 나머지는 전부 비정지.
- 큰 수 표기: `K/M/B/T` 이후 `aa, ab, ac...` 접미사(방치형 관례). 표기 유틸은 코어에 두고 렌더러가 참조한다.
- 오프라인 복귀 팝업은 **2초 이내에 닫을 수 있어야** 한다(장기 유저의 일일 마찰 1순위).

### 12.3 프로토타입 렌더러 요건

- Canvas 2D 또는 경량 DOM. 60fps 불필요(30fps 충분).
- **렌더러는 코어 상태를 읽기만 한다.** 렌더러를 제거해도 헤드리스 시뮬레이터가 동일 결과를 내야 한다(이것이 QA AX 8.2의 전제).
- 배속 버튼(×1/×10/×100/×1000)으로 시뮬레이션 결과를 눈으로 확인할 수 있게 한다.

## 13. MVP 범위와 확장 로드맵

### 13.1 MVP (코딩 에이전트 2~3주)

**목표**: "밸런스 모델 `04b`의 목표 진행 벽 표를 헤드리스로 재현하고, 그 결과를 사람이 눈으로 볼 수 있다."

| # | 항목 | 산출물 |
|---|---|---|
| M1 | 결정적 코어 | `core/` — 고정 dt=100ms, 시드 기반 RNG(**`xoshiro128**`** — 32비트 정수 연산만 사용. 빌드 플랜 가정 A-D5로 `xorshift128+`에서 대체), 순수 함수, DOM 의존 0 |
| M2 | 데이터 로더 | `data/*.json` + JSON Schema 검증. 스키마 위반 시 기동 실패 |
| M3 | 전투·스테이지·보스 | 5.5 규칙, 사냥터 자동 최적화 |
| M4 | 강화 + 자동 강화 | 5.1·5.2 |
| M5 | 장비 드랍 + 결정적 합성 | 5.3 (뼈 갈기 제외) |
| M6 | 오프라인 보상 | 상한·광고 ×2 |
| M7 | 세대 교체 + 불씨 노드(불 계열) | 4.1, 리셋/유지 표 단언 테스트 포함 |
| M8 | 헤드리스 시뮬레이터 | `sim/` — 프로파일(`f2p`/`payer`) × 30일, 목표 벽 표 출력 + ±10% 회귀 단언 |
| M9 | 분석 이벤트 발행 | 11장 스키마, 로컬 JSONL 싱크 |
| M10 | 렌더러 | 12.1의 ● 6개 화면, 배속 버튼 |
| M11 | 확률 검증 테스트 | 뼈 갈기가 확장이어도 **테스트 하네스는 MVP에 넣는다** (7.3) |

**MVP 제외 명시**: 캠프, 도감 UI, 상점 결제, 시즌 패스, 절벽, 원정, 길드, 탈것, 스킨 상점, 서버.

### 13.2 확장 로드맵

| 버전 | 내용 |
|---|---|
| v1.1 | 캠프(5.10), 도감 UI, 스킨 3종, 상점(비확률), 시즌 패스 |
| v1.2 | 절벽·원정, 주간 랭킹, 뼈 갈기(확률형 + 검증 + 천장) |
| v1.3 | 길드, 탈것 확장, 월드 2(1001~2000) |
| v2.0 | 글로벌 로컬라이즈, Steam 검토 |

### 13.3 프로토타입 성공 판정 기준

1. 헤드리스 시뮬레이터가 목표 벽 표를 **±10% 이내**로 재현한다.
2. 동일 시드 2회 실행 결과가 **바이트 단위로 동일**하다.
3. 밸런스 테이블 상수 1개를 바꾸면 곡선 diff 리포트가 자동 생성된다.
4. 신규 몬스터 1종 추가에 걸리는 시간이 **코드 변경 0줄 + 테이블 1행**이다.
