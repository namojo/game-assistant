2. 차단 (파일 · 절 · 인용 · 수정 제안)

차단 = 고객 신뢰를 잃게 하는 것(사실 오류·측정 불가 약속·규제 오해·GDD 시스템 무대응·수용 기준 없음).

B-1. GDD 7.3 확률 검증표의 전설 행이 다른 확률값(p=0.0005)으로 계산되어 있었다 — 규제 방어 증거의 근거 표 (수정 완료)

  • 파일·절: 04_gdd_primitive_brothers_2.md 7.3 「확률형 요소 — 뼈 갈기」 검증 방식 표
  • 인용(수정 전): | 0.005 (0.5%) | 0.000212 | [0.000288, 0.000712] | 42.4% | N = 1,800,000 |
  • 문제: N=100,000, p=0.005에서 3σ = 3·√(0.005·0.995/100,000) = 0.000669이고 허용 구간은 [0.004331, 0.005669], 상대오차는 **13.4%**다. 표에 적힌 0.000212 / [0.000288, 0.000712] / 42.4%는 전부 p = 0.0005(0.05%) 기준으로 계산된 값이다. 나머지 세 행(3% / 15% / 81.5%)은 전부 정확했으므로 전설 행 한 줄만 자릿수가 밀린 것이다.
  • 왜 차단인가: 이 표는 03 4.3.1이 "법적 방어 증거 생산 장치"로 규정한 확률 검증의 수치 근거이고, 05 T2.6의 수용 기준과 06 부록 E의 고객 약속이 이 표에 걸려 있다. 허용 구간 [0.000288, 0.000712]는 표기 확률 0.5%를 판정에서 항상 탈락시키는 구간이라, 그대로 구현되면 확률 검증이 영구 FAIL 한다.
  • 조치: 표 행과 바로 아래 「주의(코딩 에이전트 필독)」 문단을 정정했다(8절 G-2·G-3). 04 팀원 전달 메모 3-9의 같은 숫자도 정정했다(G-5).

B-2. 빌드 플랜 6.5 확률 검증 시행수 산식값이 자기 산식의 10배 (수정 완료)

  • 파일·절: 05_codex_build_plan.md 6.5 「확률 검증 시행수」
  • 인용(수정 전): 산식 N_i = max(100_000, ceil(900 × (1 − p_i) / p_i)) / 표의 전설 행 | 전설 | 0.005 | 1,791,000 | 1,800,000 |
  • 문제: 900 × (1−0.005)/0.005 = 900 × 199 = 179,100이다. 표의 1,791,000은 9,000 × 199로, 계수를 10배로 쓴 값이다. 같은 표의 영웅(29,100) · 희귀(5,100) · 일반(204)은 전부 900 계수로 정확히 계산돼 있어, 전설 행만 틀렸다. GDD 7.3의 "0.5%면 N ≈ 1.8e6"도 같은 오류다.
  • 왜 차단인가: 산식과 산식값이 문서 안에서 모순된다. 또 T2.6 수용 기준 5(전설 1.8e6 시행 60초 이내)가 필요량의 10배를 전제로 걸려 있어, CI 게이트가 성능 문제로 무력화될 위험이 실재한다(05 팀원 전달 메모 3에서 원저자가 T2.5의 10분 제한을 걱정한 것과 같은 축).
  • 조치: 산식값을 179,100으로 정정하고 채택 N 1,800,000은 그대로 유지하되 "산식값의 약 10배 여유(규제 증거용)"임을 명시했다. 60초를 못 지킬 경우 산식값 기준으로 내리는 합의 경로도 같은 문단에 붙였다(8절 P-3·P-4). 채택 N을 179,100 또는 200,000으로 내릴지는 기획 담당 결정 사항(6절 결정 항목 ⑦).

I-1. 로드맵 단계 번호 체계가 두 갈래 (1~4 ↔ 0~3) (수정 완료)

  • 파일·절: 01_market_analyst_brief.md 5절 「귀사는?」, 7절 머리글·표 4칸, 10절 C-2
  • 인용(수정 전): 컨설팅 로드맵 단계: **1=진단 / 2=Quick Win / 3=파이프라인화 / 4=조직화·내재화**
  • 문제: 02 8장·03 6.1·06 6.2·06b·06c는 전부 0~3이다. 특히 01 5절의 "귀사는?" 질문은 고객에게 숫자로 답하게 하는 질문이라, 그대로 쓰면 고객이 다른 체계로 답한다(06 메모 #1이 지적한 항목). 06c는 이미 0~3으로 고쳐져 있어 브리핑 원본과 미팅 키트가 서로 달랐다.
  • 조치: 01을 0~3으로 전량 통일했다(8절 M-1~M-9). 파생 표기(3~4단계 연결 → 2~3단계, 2단계 비용 회수 → 1단계, 1단계에서 점검 → 0단계, 4단계 → 3단계)까지 함께 옮겼고, "3단계 완료 시점 = 지스타 2027"은 새 체계에서 조직화 완료를 가리켜 03 6.3과 자동으로 맞아떨어지므로 그대로 두었다.
