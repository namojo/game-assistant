게임 스튜디오 AX 진단 스킬. 대상사 프로파일(사실/추정/미확인 분리), 추정 기술 스택, 업데이트 1사이클 분해, 병목 점수화(빈도×소요×인원), 스토어 리뷰 신호 분류, Quick Win 후보, 첫 미팅 진단 워크숍(세션 B) 진행안, 사전 요청 자료 목록·메일, 확인 질문 체크리스트, 관찰 포인트, 진단 기간 계획서를 작성. '스튜디오 진단', '병목 분석', '첫 미팅 준비', '사전 요청 자료', '진단 계획서', '개발 사이클 해부' 요청이나 게임사 AX 도입 전 현황 파악이 필요하면 이 스킬을 사용할 것. 시장 트렌드 조사나 전략 로드맵 작성은 대상이 아님.

Studio AX Diagnosis

게임 스튜디오의 제작·운영 사이클을 해부해 병목을 수치화하고, 첫 미팅에서 확인할 것을 설계한다.

왜 병목을 먼저 보는가

AX 컨설팅이 실패하는 첫 번째 패턴은 도구 이름을 먼저 말하는 것이다. 고객은 "팔러 왔구나"로 읽는다. 병목이 수치로 드러나면 도구는 자연스럽게 따라온다. 그래서 이 스킬의 산출물에는 도구 이름이 없다(추정 스택 확인 항목 제외).

절차

1. 프로파일 3단 분리

입력 리포트에서 항목을 세 열로 나눈다: 확인된 사실(출처) / 추정(근거) / 미확인(확인 질문). 인원·매출·스택·외주 여부는 대개 추정이다. 추정을 사실처럼 쓰면 첫 미팅에서 한 번에 신뢰를 잃는다.

2. 업데이트 1사이클 분해

references/update-cycle-template.md의 단계표를 기준으로 방치형 RPG 메이저 업데이트(예: 월드 시스템 + 스킨 + 도감 + 탈것) 1건을 분해한다. 단계마다 담당 역할·추정 소요·의존·병목 유형(손/판단/대기)을 적는다. 알 수 없는 소요는 범위(예: 2~4일)로 쓴다.

3. 병목 점수화

점수 = 발생 빈도(월) × 1회 소요(인·일) × 관여 인원. 순위표를 만들고 상위 5개에 대해 "AI가 흡수 가능한 부분 / 사람이 남아야 하는 판단"을 나눈다. 이 표가 전략가의 우선순위 매트릭스 입력이 된다.

4. 리뷰 신호 분류

스토어 리뷰·리포트의 신호를 결제/버그/밸런스/UX/CS응답/칭찬으로 분류하고, 각 신호가 QA·CS·기획 중 어디의 병목인지 연결한다. 결제 후 미수령류는 매출 직결이므로 항상 상위.

5. Quick Win 후보 3개

기준: 도입 난이도 낮음 + 체감 높음 + 진단 기간(2~3주) 내 시제품 가능. 보통 리뷰 마이닝 대시보드, CS 답변 초안, 변형 아트 자동화가 후보다. 후보마다 "미팅에서 보여줄 화면 1장"을 정의한다.

6. 첫 미팅 키트

references/first-meeting-kit.md의 구성(세션 A/B/C, 사전 요청, 체크리스트, 관찰 포인트, 어긋나는 지점)을 대상사에 맞게 채운다. 원화가·개발자 세션은 대표 없이 진행한다는 점을 명시한다. AI에 대한 감정은 대표 앞에서 나오지 않는다.

7. 진단 계획서 (2~3주)

주차별: 접근 자산(코드·에셋·시트·티켓), 인터뷰 대상, 기준선 측정 지표 4개(에셋 리드타임·업데이트 주기·회귀 버그·CS 응답시간)의 측정 방법, 산출물(진단 보고서·우선순위 확정).

출력 템플릿

# {대상사} 스튜디오 진단
## 1. 프로파일 (사실 / 추정 / 미확인)
## 2. 추정 기술 스택과 검증 질문
## 3. 업데이트 1사이클 분해표
## 4. 병목 점수표 (상위 5 + AI 흡수/사람 유지 분리)
## 5. 리뷰 신호 분류 → 병목 연결
## 6. Quick Win 후보 3 (미팅 시연 화면 포함)
## 7. 첫 미팅 키트 (세션 A/B/C 아젠다, 참석자, 사전 요청 목록·메일, 체크리스트, 관찰 포인트)
## 8. 진단 계획서 (2~3주)
## 9. 미확인 사항 총목록

첫 미팅 키트 구성 원칙

목표 문장

"진단할 수 있는 데이터를 확보하고, 게임·시장·지역을 이해했다는 신뢰를 주고, 3년 방향과 AX 범위를 합의한다." 해결책 제시는 목표가 아니다.

구조 (반나절 4시간)

  • 세션 A 경영 워크숍 90분(전원): 오프닝(플레이 소감+리뷰 마이닝 화면 1장) → 지방 게임사 이슈 1장 → 트렌드 5장+토론 → 3년 후 모습(화이트보드) → 현 게임 수명 가정 → AI에 대한 회사 입장
  • 세션 B 진단 워크숍 120분: 경영진 목표 15 → 업데이트 1건 해부 30(핵심) → 아트 세션 20(원화가, 대표 없이) → QA·기술 세션 20(개발자) → 기대와 우려 15 → 휴식 겸 개별 대화 20
  • 세션 C 종합 30분: 3년 방향(시나리오 A/B/C) × 병목 → 우선순위 초안 그 자리에서 → 다음 단계 합의

사전 요청 (D-7, NDA 후)

"가능한 것만, 없으면 '없음'이라고" 명시. 카테고리: 조직·전략 / 사업·지표 / 개발 사이클(최근 업데이트 1건 기획서·일정·분배) / 아트(원본 파일 샘플, 스타일 가이드 유무) / 밸런스(테이블 샘플, 게임 반입 경로) / QA(방식, 체크리스트, 최근 3회 핫픽스 사유) / 기술(엔진 버전, 서버, 빌드, 자동화 테스트 개수) / 운영(월 티켓 수, 리뷰 답변 프로세스)

참석자

대표 + 기획 + 원화 + 개발 각 1인 이상. 경영진만의 미팅은 절반만 본 것.

관찰 포인트

대표가 실무 질문에 직접 답하는가 / 밸런스 시트를 여는가 코드를 여는가 / "○○님만 알아요" 횟수 / 원화가의 팔짱 / 핫픽스 사유가 밸런스인가 결제인가 / 3년 그림에서 대표·실무 답이 갈리는가 / 지방 이슈 슬라이드에서 끄덕이는 항목

어긋나는 지점 (하지 말 것)

도구 이름 먼저 / 경영진만 / 범위를 아트·QA로 잠금 / Quick Win 없이 진단만 / 브리핑 30분 초과 / 대형사 사례 길게 / 지방 이슈를 동정으로

미팅 후 D+3

미팅 노트(사실/미확인/인식 차이) → 워크플로우 맵 → 시나리오·우선순위 초안 → 진단 계획서 → 누락 자료 재요청 → Quick Win 착수

방치형 RPG 메이저 업데이트 1사이클 단계표

# 단계 담당(전형) 산출물 병목 유형 전형적 함정
1 콘텐츠 기획 (월드/스킨/도감/탈것) 기획 기획서, 테이블 초안 판단 기존 곡선과의 정합성 검토 없이 확정
2 밸런스 테이블 작성 기획 시트 손+판단 시트→JSON 수동 변환, 하드코딩 상수 존재
3 원화·스프라이트 제작 원화 PSD/Spine 손 몬스터 1종 = 원화 1장이지만 변형·팔레트가 반복 노동
4 애니메이션·이펙트 원화/개발 Spine, 프리팹 손 프레임 간 일관성은 사람 필요
5 아틀라스 패킹·임포트 개발 Unity 에셋 손(대기) 수동 임포트, 명명 규칙 불일치
6 클라이언트 구현 개발 코드 판단+손 Update()에 로직 혼재, 테스트 0개
7 서버·결제·데이터 마이그레이션 개발 서버 코드, DB 판단 결제→수령 회귀 미검증
8 텍스트(도감 설명·공지·이벤트 문구) 기획 문구 손 톤 불일치, 다국어 없음
9 QA(수동 플레이) 개발/기획 겸임 체크리스트 손+대기 성장 곡선 꼬임은 200스테이지 뒤에서 발견
10 스토어 제출·심사 개발 빌드 대기 확률 표기 누락 시 반려
11 배포 후 모니터링·핫픽스 전원 패치 판단 리뷰 급증을 사람이 눈으로 확인
12 CS·리뷰 답변 기획/개발 겸임 답변 손 템플릿 답변, 결제 이슈 로그 대조 수동

병목 유형: 손(반복 노동, AI 흡수 1순위) / 판단(사람 유지, AI는 보조) / 대기(자동화·파이프라인화 대상).

점수 계산 예: 3단계 변형 아트 — 월 20종 × 0.5인·일 × 1명 = 10 / 9단계 수동 QA — 월 2회 × 3인·일 × 2명 = 12 / 12단계 CS — 월 300건 × 0.05인·일 × 1명 = 15. 숫자는 확인 전까지 범위로 쓴다.
