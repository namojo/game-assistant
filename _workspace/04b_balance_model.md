## 2. 스테이지 · 몬스터

### 2.1 수식

```
HP(s)      = HP0 · g_hp^(s-1) · (1 + a_step · floor(s / 10))
HP_boss(s) = HP(s) · m_boss                    (s mod 10 == 0)
G(s)       = G0 · g_gold^(s-1)
G_boss(s)  = G(s) · boss_gold_mult
n(s)       = n_mob                              (일반 스테이지 몬스터 수)
```

### 2.2 확정 파라미터

| 파라미터 | 값 | 참조 범위 | 선정 이유 |
|---|---|---|---|
| `HP0` | **25.0** | 10~30 | 1레벨 형님(ATK 6.0)이 첫 몬스터를 약 4초에 잡는다 |
| `g_hp` | **1.058** | 1.06~1.10 | 범위 하한보다 약간 낮다. 30일 도달 스테이지를 950 수준으로 만들기 위한 조정(8.3 이력 #4) |
| `a_step` | **0.25** | 0.05~0.15 | **범위를 크게 벗어남(의도적)**. 계단항은 초반을 강하게, 후반을 약하게 누르는 유일한 레버다(8.3 이력 #3). s=50에서 ×2.25, s=950에서 ×24.75 |
| `m_boss` | **7.0** | 5~10 | 보스 벽이 일반 벽보다 항상 먼저 오도록(4.3) |
| `boss_timer` | **30초** | 30 | 벽 판정 기준 |
| `n_mob` | **4** | 3~5 | |
| `G0` | **8.0** | — | `HP0`와의 비를 통해 초반 강화 속도 결정 |
| `g_gold` | **1.052** | `g_hp − 0.01` 권장 → 1.048 | `g_hp − 0.006`. 권장보다 좁혀 후반 파밍 정체를 완화 |
| `boss_gold_mult` | **10.0** | — | 보스 처치가 체감 보상이 되도록 |
| `t_min_kill` | **0.5초** | — | 몬스터 1마리 최소 처치 시간. **`f*` 정의의 근거** |

## 3. 플레이어 전투력

### 3.1 수식

```
ATK_i(L)   = atk0_i · (1 + b · L) · g_atk^floor(L / 25)
atk0_i     = ATK0 · 4^i          (i = 0..5)
DPS_base   = Σ_{i ∈ 해금} ATK_i(L_i)
E(s)       = equip_mult^min(floor(s / equip_span), 40)      (장비, 런 내 스테이지 종속)
M          = node_effect^A                                   (불씨 노드, 영구)
DPS_total  = DPS_base · E(s) · M · (1 + 카드%) · 패키지배수
```

### 3.2 확정 파라미터

| 파라미터 | 값 | 참조 범위 | 이유 |
|---|---|---|---|
| `ATK0` | **6.0** | — | `HP0=25` 대비 첫 킬 약 4초 |
| `b` | **0.12** | 0.1~0.2 | 선형 항 |
| `g_atk` | **1.75** | 1.5~2.0 | 25레벨마다 ×1.75 점프(연출 이벤트) |
| `step_every` | **25** | 25 | |
| 형님 수 | **6종** (MVP 4종) | — | 해금 `unlock_stage = [1, 12, 35, 75, 150, 280]` |
| `equip_mult` | **1.20** | 1.3~1.6 | **범위 하한 미만(의도적)**. 장비를 런 내 변수로 두었기 때문에 배수가 크면 곡선이 스테이지 종속으로 붕괴한다 |
| `equip_span` | **60** | — | 60스테이지마다 등급 1 상승 |
| `merge_count` | **4** | 3~5 | 결정적 합성(확률 없음) |

## 4. 경제

### 4.1 강화 비용

```
C_i(L) = cost0_i · g_cost^L ,      cost0_i = C0 · 4^i
L_max ≈ log(G_total · (g_cost − 1) / cost0 + 1) / log(g_cost)
```

| 파라미터 | 값 | 참조 범위 | 이유 |
|---|---|---|---|
| `C0` | **25.0** | — | `G0=8`, `n_mob=4` → 첫 웨이브 32골드 = 첫 강화 1회 |
| `g_cost` | **1.075** | 1.07~1.12 | `g_gold=1.052`보다 커야 벽이 생긴다. 차 0.023이 벽 형성 속도를 결정 |

### 4.2 골드 수입률

```
rate(s) = G(s) / max( HP(s) / DPS_total , t_min_kill )
```

### 4.3 최적 사냥터 `f*` (핵심 파생식)

`rate(s)`는 "한 방에 죽는 구간"에서는 `G(s)/t_min_kill`로 **스테이지에 비례해 증가**하고, 그 이후에는 `DPS·G(s)/HP(s)`로 **감소**한다. 따라서 최댓값은 경계에서 나온다.

```
f* = max { s : HP(s) ≤ DPS_total · t_min_kill }
rate(f*) = G(f*) / t_min_kill
```

**전선과의 간격 (g_hp = 1.058 기준)**

| 구분 | 조건 | `f*` 대비 HP 비 | 스테이지 간격 |
|---|---|---|---|
| 최적 사냥터 `f*` | `HP = 0.5 · DPS` | 1.0 | 0 |
| 보스 전선 | `7·HP/DPS = 30` → `HP = 4.286·DPS` | 8.57배 | **+38.1** |
| 일반 웨이브 전선 | `4·HP/DPS = 30` → `HP = 7.5·DPS` | 15.0배 | +48.0 |

→ **보스 전선이 일반 전선보다 약 10스테이지 낮다.** 벽은 항상 보스에서 온다. 계단항 `a_step`이 있어 실제 간격은 스테이지에 따라 이보다 약간 좁다.

> 이 계산이 GDD 5.5 「사냥터 자동 최적화」의 근거다. 유저가 손으로 `f*`를 찾게 두면 안 된다.

### 4.4 인플레이션 규칙

이벤트/보상 크기는 절대 수치가 아니라 **해당 시점 1시간 골드 수입의 배수**로 정의한다.

```
1시간 수입 = 3600 · rate(f*)
```

| 보상 | 배수 |
|---|---|
| 일일 출석 | 1.0 h |
| 광고 즉시 골드 | 0.5 h |
| 오프라인 8h (무과금) | 4.8 h |
| 오프라인 8h + 광고 ×2 | 9.6 h |
| 오프라인 12h (패스) | 7.2 h |
| 기간 보스 | 3.0 ~ 10.0 h |

## 5. 오프라인 보상

```
R_off = min(t_off, T_cap) · rate(f*) · r_off · (광고 시 × ad_mult)
```

| 파라미터 | 값 | 이유 |
|---|---|---|
| `T_cap` | **28,800초 (8시간)** | 참조 범위 8~12h의 하한. 상한이 낮아야 1일 2세션 설계가 성립 |
| `r_off` | **0.60** | 참조 범위 0.5~0.8 중간 |
| `ad_mult` | **2.0** | |
| 패스 보유 시 `T_cap` | **43,200초 (12시간)** | `p_season_pass` |
| 탈것 추가 | 최대 `+14,400초` | |

| 조건 | 유효 수입 시간 |
|---|---|
| 무과금 8h | `8 × 0.6 = 4.8 h` |
| 무과금 8h + 광고 | `9.6 h` |

## 6. 프레스티지 (세대 교체 / 「빙하기」)

### 6.1 불씨 산출

```
Q = floor( ember_c · s_reached^ember_p )
```

| 파라미터 | 값 | 참조 범위 |
|---|---|---|
| `ember_c` | **0.35** | — |
| `ember_p` | **1.45** | 1.3~1.6 |

| 도달 s | 120 | 138 | 200 | 360 | 450 | 700 | 950 | 1150 |
|---|---|---|---|---|---|---|---|---|
| Q | 362 | 443 | 759 | 1,781 | 2,461 | 4,671 | 7,273 | 9,595 |

### 6.2 불씨 노드 — **등차 비용을 채택한 이유** (중요)

```
cost(A) = node_cost_base + node_cost_slope · A      ← 등차(arithmetic)
누적(A) = node_cost_base · A + node_cost_slope · A(A−1)/2
M       = node_effect^A                             ← 지수
```

| 파라미터 | 값 |
|---|---|
| `node_cost_base` | **5.0** |
| `node_cost_slope` | **0.7** |
| `node_effect` | **1.05** |

| A | 10 | 50 | 100 | 200 | 400 | 589 | 724 |
|---|---|---|---|---|---|---|---|
| 누적 불씨 | 82 | 1,108 | 3,965 | 14,930 | 57,860 | 124,161 | 188,000 |
| M | 1.63 | 11.5 | 132 | 1.73e4 | 2.99e8 | **3.02e12** | 1.43e15 |

**왜 등비(`g_node^A`)를 쓰지 않았는가.** 등비 비용이면 `A ∝ ln(E)`이므로 `M = node_effect^A = E^(ln 1.05 / ln g_node)` — 즉 `M`이 누적 불씨 `E`의 **거듭제곱**에 그친다. 그런데 `Q = 0.35·s^1.45`도 다항식이므로 `E`는 다항식으로만 자란다. 결과적으로 30일차 `M`이 1e2 수준에 머문다.

한편 도달 스테이지의 상한은 대략 다음 관계를 만족한다.

```
런 내 DPS 성장률 (스테이지당) ≈ g_gold^α · equip_mult^(1/equip_span)   (α = ln g_atk_eff / ln g_cost)
스테이지당 부족분  δ = ln(g_hp·계단) − ln(런 내 DPS 성장률)
s_max ≈ ln(M) / δ + 상수
```

`δ ≈ 0.020` 근방이므로 `s_max`를 120 → 950으로 올리려면 `ln M`이 약 **17 증가**해야 한다(`M` 배수 약 2.4e7). 등비 노드로는 불가능하고, **등차 노드**여야 `A ∝ √E`, `M = 1.05^(√(2E/0.7))` 로 `E`에 대해 준지수적으로 자란다. 실측 A=589에서 `M = 3.02e12`로 요구치를 충분히 만족한다.

> **미검증 리스크**: 등차 비용은 상한이 없으므로 60일·90일 구간에서 인플레가 가속될 수 있다. GDD 팀원 전달 메모 3-8에 회신 요청으로 등록했다.

### 6.3 프레스티지 트리거

```
해금:    best_ever ≥ prestige_min_stage (= 120)
권장선:  run_best ≥ prestige_ratio_hint × last_best   (= 1.15)
정체 감지: 최근 window_sec(1800초) 동안 run_best 증가 < window_gain(5)
시작 스테이지: start_stage = max(1, floor(start_stage_ratio × best_ever)),  start_stage_ratio = 0.5
```

시뮬레이터 정책: 권장선 도달 **또는** 정체 감지 시 즉시 프레스티지(합리적 유저 근사).

## 7. 목표 진행 벽 표 (수식 확정 **전에** 작성한 설계 의도)

- **무과금**: 일 2세션(60분 + 30분 = 90분 활성), 오프라인 상한 8h, 광고 오프라인 ×2 사용
- **소과금 (월 13,200원 = 시즌 패스 9,900 + 성장 패키지 I 3,300)**: 일 2세션(60분 + 35분 = 95분 활성), 오프라인 상한 12h, 골드 ×1.20, DPS ×1.12, 광고 사용

| 시점 | 무과금 도달 s | 소과금 도달 s | 첫 벽 체감 | 프레스티지 횟수 (무/소) |
|---|---|---|---|---|
| 1시간 | **105** | **120** | — (직후) | 0 / 0~1 |
| D1 | **140** | **210** | **약 55분, s≈110 (보스 벽)** | 2 / 5 |
| D3 | **350** | **400** | 세대 교체가 주기화 | 8 / 10 |
| D7 | **450** | **520** | 노드 체감 구간 진입 | 12 / 16 |
| D30 | **950** | **1,150** | 월드 1 후반 | 35 / 43 |

**설계 의도**
- 첫 벽을 1시간 안에 반드시 보여준다. 벽을 못 본 유저는 프레스티지의 의미를 이해하지 못한다.
- D1 안에 프레스티지 2회. "리셋하면 더 빨라진다"를 첫날 몸으로 배우게 한다.
- 소과금/무과금 도달 격차는 D30에서 **1.2배 이내**로 묶는다. 이 이상 벌어지면 무과금 이탈, 이하면 결제 동기 소멸.
- D30에서 월드 1(1~1000)을 막 넘기게 한다. 콘텐츠 소비 속도와 업데이트 주기(28일 시즌)를 맞춘다.

## 8. 검산 (`balance-math.md` 8절 절차)

검산은 `references/balance-math.md` 8절의 4단계를 그대로 수행했다. 실행 환경: Python 3, 결정적 시뮬레이터(9절 스펙과 동일 로직).

### 8.1 절차 1·2 — 누적 골드 → `L_max` → DPS → 클리어 가능 `s` (해석 재계산)

### 8.4 절차 4 — 확률 시스템 검증 기준

표기 확률 `p`에 대해 `N` 시행 관측 빈도가 `p ± 3√(p(1−p)/N)` 안에 있어야 한다.

| 표기 p | 시스템 | ±3σ (N=100,000) | 허용 구간 | 상대오차 | **권장 N** |
|---|---|---|---|---|---|
| 0.005 | 뼈 갈기 전설 | 0.000212 | [0.000288, 0.000712] | **42.4%** | **1,800,000** |
| 0.03 | 뼈 갈기 영웅 | 0.001618 | [0.028382, 0.031618] | 5.4% | 100,000 |
| 0.15 | 뼈 갈기 희귀 | 0.003387 | [0.146613, 0.153387] | 2.3% | 100,000 |
| 0.815 | 뼈 갈기 일반 | 0.003676 | [0.811324, 0.818676] | 0.5% | 100,000 |

**시행수 산정식** (상대오차 ±10% 기준): `N ≥ 900 · (1 − p) / p`

| p | 0.5% | 1% | 3% | 5% | 10% |
|---|---|---|---|---|---|
| 필요 N | 1,791,000 | 89,100 | 29,100 | 17,100 | 8,100 |

**천장 단언(결정적)**: 40회 연속 시행을 1,000회 반복할 때 전설 미획득 케이스 **0건**. 20회 시점 영웅 이상 확정도 동일하게 단언한다.

**결정적 합성 단언**: 동일 등급 4개 → 상위 1개는 **성공률 100%**이므로 확률 테스트 대상이 아니다. 대신 "소모 4개 / 생성 1개 / 등급 +1"의 불변식을 단언한다.

```
while (timeLeft > 0) {
  dps = computeDps();                                   // 3.1
  if (canClear(s, dps)) {                               // 3.3 벽 판정의 역
     tw = (s % 10 == 0) ? m_boss*HP(s)/dps : n_mob*HP(s)/dps;
     tw = max(tw, t_min_kill * (s % 10 == 0 ? 1 : n_mob));
     advance(tw); gold += (s%10==0 ? boss_gold_mult : n_mob) * G(s) * goldMult;
     buyGreedy(); s += 1; runBest = max(runBest, s);
     recordHistory(t, runBest); checkPrestige();
  } else {
     dt = min(60, timeLeft);
     advance(dt); gold += rate(fStar(dps)) * dt;        // 4.2 / 4.3
     buyGreedy();
     if (stall > 600 && firstWall == null) firstWall = t;
     checkPrestige();
  }
}
```

### 9.3 `buyGreedy` 규칙

```
반복 {
  후보 = 해금된 형님 중 C_i(L_i) ≤ gold 인 것
  선택 = argmax( ΔATK_i / C_i(L_i) )
  동률이면 slot 오름차순              ← 결정성 보장에 필수
  없으면 종료
  gold -= C_i(L_i); L_i += 1
}
```
