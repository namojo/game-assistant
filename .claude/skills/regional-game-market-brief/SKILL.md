# Regional Game Market Brief

게임사 컨설팅 첫 미팅 세션 A(경영 워크숍) 재료가 되는 시장·지역·정책 브리핑을 작성한다.

## 왜 이 형식인가
컨설팅에서 트렌드 브리핑은 세미나가 되기 쉽다. 브리핑의 목적은 정보 전달이 아니라 **대표가 자기 회사의 방향을 말하게 하는 것**이다. 그래서 트렌드 1개마다 "대상사 함의" 1개와 "귀사는?" 질문 1개를 붙이고, 5개 축으로 제한한다.

## 5개 축

| 축 | 다룰 내용 | 대상사 함의의 방향 |
|---|---|---|
| 1. 장르 | 해당 장르의 성장·대형사 진입·레드오션 신호 | 선점 효과 방어, 신작 장르 선택 |
| 2. 시장 | 다운로드 정체·IAP 심화·플레이 시간 | 신규 획득 vs 기존 유저 LTV |
| 3. 수익모델·규제 | 확률형 규제, 비확률 수익(스킨·패스) 이동 | 확률 검증 자동화, 아트 생산량과 수익모델 연결 |
| 4. AI 도입 | 검증의 해, 측정 가능 업무 집중, 개발자 부정 인식, AI 아트 유저 반발, 스토어 고지 정책 | 거버넌스 먼저, 공개 범위 사전 결정 |
| 5. 지역·지원 | 수도권 집중, 인력 유출, 지역 지원사업·펀드·전시 | 지원사업 연계 단계, 부산의 역설적 강점 |

## 절차

1. `_workspace/00_input/`의 내부 리포트에서 5개 축에 해당하는 사실을 먼저 추출한다. 이미 정리된 것을 재조사하는 것은 낭비다.
2. 공백을 확인한다. 보통 공백은 (a) 경쟁작 비교표, (b) 지원사업 다음 회차 일정, (c) 최신 규제 동향이다. 웹 조사는 공백에만 쓴다.
3. 경쟁작 비교: 같은 장르 3~4개를 골라 `references/competitor-table.md` 형식으로 정리한다. 스토어 공개 정보(업데이트 주기·평점·수익모델 노출 방식)만 쓰고, 매출 추정은 출처 없이 쓰지 않는다.
4. 지원사업: `references/busan-support-programs.md`를 기준으로 확인·갱신하고, 컨설팅 로드맵 단계(진단/Quick Win/파이프라인화/조직화)와 매핑한다.
5. 축마다 `함의 → 귀사는? 질문` 을 작성한다. 질문은 예/아니오가 아니라 숫자나 선택을 답하게 만든다("활성 유저는 몇 명이고 콘텐츠 소비 속도를 따라가는가").
6. 출처 목록과 "추가 조사 필요" 섹션으로 마무리한다.

## 출력 템플릿

```markdown
# {대상사} 시장·지역·정책 브리핑
작성일 / 대상 / 용도(첫 미팅 세션 A 재료)

## 0. 한 장 요약
- 5개 축 각 1문장 + 대상사에 가장 아픈 축 1개 지목

## 1. 장르 … ## 5. 지역·지원
각 축: 사실(출처) → 대상사 함의 → 귀사는? 질문

## 6. 경쟁작 비교표
## 7. 활용 가능 지원사업 (일정·요건·컨설팅 단계 매핑)
## 8. 지방 게임사 공통 이슈 1장 (구조 → 역설적 강점으로 바로 연결)
## 9. 출처
## 10. 추가 조사 필요
```

## 톤 규칙
- 대형사 사례는 1줄. 비교 대상이 아니라 배경이다.
- 지방 이슈는 동정 없이 구조로 쓰고 같은 단락 안에서 강점으로 넘어간다.
- 수치에는 연도와 출처를 붙인다. 컨설턴트가 그 자리에서 근거를 요구받는다.

## 공통 규약
로드맵 단계 번호는 항상 `0 진단 / 1 Quick Win / 2 파이프라인화 / 3 조직화`를 쓴다. 문서마다 번호 체계가 다르면 고객이 다른 체계로 답하게 되고, 검수에서 실제로 이 불일치가 발견되었다.

- `references/competitor-table.md` — 경쟁작 비교표 형식과 관찰 항목
