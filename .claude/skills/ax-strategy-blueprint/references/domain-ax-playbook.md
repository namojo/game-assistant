# 영역별 AX 플레이북 (방치형 RPG 소규모 스튜디오 기준안)

## 목차
1. 아트 2. QA 3. 밸런스·기획 4. CS·커뮤니티 5. 개발 생산성 6. 텍스트·로컬라이즈 7. 데이터 8. UA·마케팅 9. 신작 프로토타이핑

## 1. 아트 — "생성"이 아니라 "스타일 일관성 파이프라인"
- 문제: 300번째 몬스터가 1번째와 다른 그림이 되는 것이 실패 패턴. 목표는 자사 스타일을 학습한 생산 라인.
- 구성: 자사 원화로 스타일 모델(LoRA) → 컨셉 탐색은 상용 모델, 프로덕션은 로컬 파이프라인+자체 스타일 → 변형 자동화 우선(등급별 팔레트·스킨 의상·색상/크기 변형) → Vision LLM 자동 검수(팔레트·선 굵기·실루엣·해상도) → 아틀라스 패킹·엔진 임포트 자동화
- 한계: 스프라이트 애니메이션 프레임 간 일관성은 사람 손 필요
- 거버넌스: 학습 데이터 자사 IP 한정 / 핵심 캐릭터 원화는 사람 / 유저 공개 범위 사전 결정 / 원화가 → 아트 디렉터·큐레이터
- 지표: 에셋 1종당 리드타임, 월간 신규 에셋 수, 검수 반려율

## 2. QA — "화면 테스트"가 아니라 "수치 시뮬레이션"
- 문제: 방치형은 버그보다 성장 곡선 꼬임이 치명적. 상수 하나가 200스테이지 뒤에서 벽으로 나타남.
- 구성: 전투 로직을 엔진 컴포넌트에서 분리한 순수 클래스 → 헤드리스 시뮬레이터(몬테카를로 가상 유저, 곡선 diff 리포트) → 확률 검증(표기 vs 구현 일치) → 결제·수령 회귀 시나리오 → Vision LLM 플레이 에이전트(UI 깨짐·소프트락) → 리뷰 마이닝(버전별 불만 급증) → 크래시 트리아지
- 전제: 전투 로직 분리 리팩터링 선행(5번과 연결)
- 지표: 배포 후 회귀 버그 수, 핫픽스 빈도, 밸런스 긴급 패치 수

## 3. 밸런스·기획 코파일럿
- 시트에 자연어 질의·수정 → 시뮬레이터 연결("이 수치면 D7 벽이 어디로") → 신규 콘텍스트 정합성 자동 체크 → 이벤트 보상 인플레이션 예측
- 사람 개입: 최종 수치 확정

## 4. CS·커뮤니티 (Quick Win)
- 티켓·리뷰 분류(버그/결제/밸런스/제안/칭찬) → FAQ 기반 1차 답변 초안(GM 검토 후 발송) → 결제 티켓은 서버 로그 자동 대조 → 공지·이벤트 문구 초안(톤 가이드)
- 도입 비용 최저·체감 최고. 진단 기간 병행 구축.
- 지표: CS 1차 응답 시간

## 5. 개발 생산성과 코드 자산화
- 코드 문서화 → 아키텍처 맵 → 테스트 보강 → 전투 로직 분리 순. 엔진(Unity/C#)은 AI 코딩 도구가 잘하는 영역.
- 지방 게임사 특유 효과: 이직 시 지식 유실 방지(지식 자산화)

## 6. 텍스트·로컬라이즈
- 도감·이벤트·대사 톤 가이드 기반 대량 생산 → 용어집 + LLM 번역 + 네이티브 검수 1회
- 시나리오 B 전제. 콘진원 게임더하기 연계 가능

## 7. 데이터
- Text-to-SQL 분석 에이전트(데이터 분석가 채용 대체) → 코호트 잔존·결제 전환·이탈 직전 행동 정기 리포트 → 리뷰 마이닝과 결합

## 8. UA·마케팅
- 크리에이티브 대량 생성·A/B 자동화 → ASO 문구 → 국가별 변형

## 9. 신작 프로토타이핑
- 컨셉 → 플레이어블 1~2주. 기존 스타일 모델·밸런스 프레임워크·시뮬레이터·운영 에이전트 재사용.
- 신작은 처음부터 시뮬레이터-퍼스트·데이터 주도 아키텍처로 만들어 QA AX의 전제 조건(로직 분리)을 리팩터링 없이 확보한다.
