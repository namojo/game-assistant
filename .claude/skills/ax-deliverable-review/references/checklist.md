# 검수 체크리스트

## A. 경계면 정합성
- [ ] KPI: 기획서·요약·전략 청사진의 KPI가 정확히 같은 4개인가 (에셋 리드타임 / 업데이트 주기 / 회귀 버그 수 / CS 1차 응답 시간)
- [ ] 시나리오 A/B/C 명칭·정의가 시장 브리핑·전략·기획서에서 동일한가
- [ ] 진단의 병목 상위 5 순서와 전략의 우선순위가 일치하거나, 불일치 이유가 병기되었는가
- [ ] Quick Win 후보 3개가 진단·전략·기획서에서 같은가
- [ ] 로드맵 4단계 기간이 전략·기획서·일정표에서 같은가
- [ ] GDD 3·4장의 벽 정의 수치가 밸런스 모델 목표 벽 표와 같은가
- [ ] GDD 5장 모든 시스템이 빌드 플랜 대응표에서 최소 1개 태스크를 갖는가
- [ ] GDD 8장 스키마와 빌드 플랜 3장 스키마의 필드가 같은가
- [ ] AGENTS.md의 명령이 빌드 플랜 수용 기준의 명령과 같은가

## B. 컨설팅 원칙
- [ ] 기획서 첫 3페이지(배경·이해·진단 가설)에 도구·제품 이름이 없는가
- [ ] "생산성 향상", "혁신", "효율화" 등 측정 불가 약속이 KPI 자리에 없는가
- [ ] 확인된 사실 / 추정 / 미확인이 모든 문서에서 구분 표시되는가 (인원·매출·스택은 대개 추정)
- [ ] 대형사 사례가 문서당 1~2줄 이내인가
- [ ] 지방 게임사 이슈가 동정 어조 없이 구조 → 강점으로 이어지는가
- [ ] 각 AX 영역에 한계와 사람 개입 지점이 명시되었는가
- [ ] 거버넌스 5문서(AI 활용 원칙·스타일 가이드·권한 정책·데이터 정책·역할 정의서)가 전략과 기획서에 모두 있는가
- [ ] 확률형 아이템: 표기 vs 구현 검증 방식이 QA 방안과 GDD 수익모델 양쪽에 있는가
- [ ] 컨설턴트 의존 종료 시점이 로드맵에 있는가

## C. 빌드 플랜 실행 가능성
- [ ] 모든 태스크에 실행 명령 + 기대 결과 형식의 수용 기준이 있는가
- [ ] 크기 L 태스크가 분할되었는가
- [ ] 코어 패키지 무의존·`Math.random` 금지·시드 RNG 규칙이 AGENTS.md에 있는가
- [ ] 밸런스 수치가 `data/balance.json`으로 모이고 하드코딩 금지 규칙이 있는가
- [ ] 시뮬레이터 결정성 테스트(같은 시드 = 같은 출력)가 있는가
- [ ] 밸런스 회귀 허용 오차와 확률 검증 N·신뢰구간이 숫자로 있는가
- [ ] 저장 포맷에 schemaVersion과 마이그레이션 규칙이 있는가

## D. 가정 승격
빌드 플랜·GDD의 "가정" 항목 중 첫 미팅에서 고객이 답할 수 있는 것(전작 시스템 상세, 스택, 외주 여부)은 리포트 6장에 모아 첫 미팅 확인 항목으로 승격한다.
