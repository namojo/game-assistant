# Studio AX Diagnosis

게임 스튜디오의 제작·운영 사이클을 해부해 병목을 수치화하고, 첫 미팅에서 확인할 것을 설계한다.

## 왜 병목을 먼저 보는가
AX 컨설팅이 실패하는 첫 번째 패턴은 도구 이름을 먼저 말하는 것이다. 고객은 "팔러 왔구나"로 읽는다. 병목이 수치로 드러나면 도구는 자연스럽게 따라온다. 그래서 이 스킬의 산출물에는 도구 이름이 없다(추정 스택 확인 항목 제외).

## 절차

### 1. 프로파일 3단 분리
입력 리포트에서 항목을 세 열로 나눈다: **확인된 사실(출처)** / **추정(근거)** / **미확인(확인 질문)**. 인원·매출·스택·외주 여부는 대개 추정이다. 추정을 사실처럼 쓰면 첫 미팅에서 한 번에 신뢰를 잃는다.

### 2. 업데이트 1사이클 분해
`references/update-cycle-template.md`의 단계표를 기준으로 방치형 RPG 메이저 업데이트(예: 월드 시스템 + 스킨 + 도감 + 탈것) 1건을 분해한다. 단계마다 담당 역할·추정 소요·의존·병목 유형(손/판단/대기)을 적는다. 알 수 없는 소요는 범위(예: 2~4일)로 쓴다.

### 3. 병목 점수화
`점수 = 발생 빈도(월) × 1회 소요(인·일) × 관여 인원`. 순위표를 만들고 상위 5개에 대해 "AI가 흡수 가능한 부분 / 사람이 남아야 하는 판단"을 나눈다. 이 표가 전략가의 우선순위 매트릭스 입력이 된다.

### 4. 리뷰 신호 분류
스토어 리뷰·리포트의 신호를 결제/버그/밸런스/UX/CS응답/칭찬으로 분류하고, 각 신호가 QA·CS·기획 중 어디의 병목인지 연결한다. 결제 후 미수령류는 매출 직결이므로 항상 상위.

### 5. Quick Win 후보 3개
기준: 도입 난이도 낮음 + 체감 높음 + 진단 기간(2~3주) 내 시제품 가능. 보통 리뷰 마이닝 대시보드, CS 답변 초안, 변형 아트 자동화가 후보다. 후보마다 "미팅에서 보여줄 화면 1장"을 정의한다.

### 6. 첫 미팅 키트
`references/first-meeting-kit.md`의 구성(세션 A/B/C, 사전 요청, 체크리스트, 관찰 포인트, 어긋나는 지점)을 대상사에 맞게 채운다. 원화가·개발자 세션은 대표 없이 진행한다는 점을 명시한다. AI에 대한 감정은 대표 앞에서 나오지 않는다.

### 7. 진단 계획서 (2~3주)
주차별: 접근 자산(코드·에셋·시트·티켓), 인터뷰 대상, 기준선 측정 지표 4개(에셋 리드타임·업데이트 주기·회귀 버그·CS 응답시간)의 측정 방법, 산출물(진단 보고서·우선순위 확정).

## 출력 템플릿

```markdown
# {대상사} 스튜디오 진단
## 1. 프로파일 (사실 / 추정 / 미확인)
## 2. 추정 기술 스택과 검증 질문
## 3. 업데이트 1사이클 분해표
## 4. 병목 점수표 (상위 5 + AI 흡수/사람 유지 분리)
## 5. 리뷰 신호 분류 → 병목 연결
## 6. Quick Win 후보 3 (미팅 시연 화면 포함)
## 7. 첫 미팅 키트 (세션 A/B/C 아젠다, 참석자, 사전 요청 목록·메일, 체크리스트, 관찰 포인트)
## 8. 진단 계획서 (2~3주)
## 9. 미확인 사항 총목록
```
