게임사 대표·실무진에게 제출하는 AX 컨설팅 기획서(제안서)·경영진 요약·첫 미팅 키트 작성 스킬. 시장 브리핑·진단·전략 청사진을 고객 언어로 번역하고, 도구 이름 우선 금지·4대 KPI만 약속·지방 게임사 구조 프레임·산출물/단계/일정/투입 구조를 갖춘 문서를 만든다. 'AX 컨설팅 기획서', '제안서 써줘', '경영진 요약', '고객 제출용 문서', '컨설팅 제안 범위·일정' 요청이나 내부 분석을 고객 제출 문서로 바꿔야 하면 이 스킬을 사용할 것. 내부 분석·전략 설계 자체는 다른 스킬이 담당.

AX Proposal Writer

내부 분석 문서를 고객이 30분 안에 읽고 결정할 수 있는 기획서로 바꾼다.

독자 모델

9명 회사의 대표는 (1) 바쁘고, (2) "AI 팔러 온 사람"을 경계하며, (3) 대형사 사례에 지치고, (4) 자기 게임을 이해한 사람에게만 데이터를 준다. 기획서의 첫 임무는 설득이 아니라 이해했음을 증명하는 것이다.

절차

  1. 핵심 메시지 3개를 전략 청사진에서 뽑는다. 기본형: ① 지방 게임사의 약점은 에이전트로 상쇄 가능한 종류다 ② 요청 분야(아트·QA)에서 증명하고 전체 사이클로 확장한다 ③ 측정 가능한 4개 지표로만 약속하고 컨설턴트 의존은 종료 시점이 있다.
  2. 경영진 요약 1장(06b): 배경 3줄, 진단 가설 3줄, 제안 3단계, KPI 4개, 다음 단계 1개.
  3. 본 기획서(06): references/proposal-template.md 목차. 첫 3페이지(배경·이해·진단 가설)에 도구 이름 금지. 도구는 부록 "하네스 구성 예시"에만.
  4. 첫 미팅 키트(06c): 진단 문서의 미팅 구성·사전 요청 목록·메일 초안을 제출 가능한 형태(고객 시점 문장)로 정리.
  5. 정합성 자체 점검: KPI 4개가 전략 문서와 동일한가, 시나리오 A/B/C 명칭이 같은가, 신작은 1~2페이지 트랙 소개로만 다루고 상세는 별첨 GDD로 넘겼는가.

톤 규칙

  • 문장은 짧게. 표는 결정에 필요한 것만. 경영진은 표를, 실무진은 부록을 읽는다.
  • "생산성 향상", "혁신" 같은 측정 불가 어휘 금지. 대신 "에셋 1종당 리드타임 단축".
  • 지방 게임사 이슈는 구조로 쓰고 같은 단락에서 역설적 강점(의사결정 속도·자사 IP 데이터·유저 관계·부산 인프라)으로 넘어간다.
  • 한계를 먼저 말한다(예: 스프라이트 프레임 일관성은 사람 필요). 한계가 신뢰다.
  • 사실/추정 표시를 유지한다. 내부 문서의 (추정)을 기획서에서 지우지 않는다.
  • 비용은 금액 대신 투입 구조(단계별 기간·컨설턴트 투입 형태·고객 측 참여 시간)로 쓴다. 금액은 사용자가 지정할 때만.

공통 규약

로드맵 단계 번호는 항상 0 진단 / 1 Quick Win / 2 파이프라인화 / 3 조직화를 쓴다. 문서마다 번호 체계가 다르면 고객이 다른 체계로 답하게 되고, 검수에서 실제로 이 불일치가 발견되었다.

기획서 목차 (분량 가이드: A4 12~18장)

표지: {대상사} AX 컨설팅 기획서 / 제안 조직 / 일자 / 문서 버전
0. 경영진 요약 (1장) — 별도 파일로도 제공
1. 제안 배경 (1장) — 시장 3줄·지역 3줄·대상사 3줄. 도구 이름 없음
2. 우리가 이해한 {대상사} (1~2장) — 확인된 사실 표, 스토어 리뷰에서 읽은 신호, 한 문장 정의("9명이 8년째 굴리는 콘텐츠 공장"), (추정) 표시 유지
3. 지방 게임사의 구조적 이슈와 역설적 강점 (1장)
4. 진단 가설 (1장) — 업데이트 사이클의 병목 상위 5, Quick Win 후보 3. "첫 미팅·진단에서 검증"
5. 접근 방법 (1~2장) — 진단→연결→증명→확장→내재화 논리, 컨설팅 원칙 5개(병목 먼저·측정 가능만·역할 재정의 선행·단일 진입점·자사 데이터 우선)
6. 제안 범위와 단계 (2장) — 0 진단 / 1 Quick Win / 2 파이프라인화 / 3 조직화. 단계별 기간·활동·산출물·고객 측 참여
7. 3년 시나리오와 AX 우선순위 (1장) — A/B/C 표, "첫 미팅에서 무게 중심 확인"
8. 신작 프로토타이핑 트랙 (1~2장) — 시나리오 C 옵션. 시뮬레이터-퍼스트 원칙, 기존 자산 재사용, 별첨 GDD·빌드 플랜 안내
9. 성과 지표 (1장) — 4대 KPI 표(측정 방법·기준선 측정 시점·목표 방향) + 보조 지표 분리
10. 거버넌스와 리스크 (1장) — 5문서, 상위 리스크 5개와 대응
11. 일정과 투입 구조 (1장) — 간트 표, 컨설턴트 투입 형태, 고객 측 역할(아트 디렉터·QA 오너·에이전트 운영자 지정)
12. 다음 단계 (½장) — NDA → 사전 자료 → 첫 미팅(반나절) → 진단 착수
부록 A. 첫 미팅 아젠다 요약  부록 B. 사전 요청 자료 목록  부록 C. 하네스 구성 예시(도구 이름 허용)  부록 D. 활용 가능 지원사업  부록 E. 용어
